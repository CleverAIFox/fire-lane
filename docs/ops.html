2 · 하루 흐름

아침 — 내려받고 시작
이걸 빼먹으면 사흘 뒤 대형 충돌이 난다
git switch part/gis
git merge origin/dev      # ★ 남들 작업 반영
git switch -c feat/gis-작업명
저녁 — 올리고 끝낸다
완성해야 푸시하는 게 아니라 동작하는 지점마다 푸시한다
git push -u origin feat/gis-작업명

# PR:  base: part/gis  ←  compare: 내 브랜치
# 머지 후 브랜치 삭제 (자동)

4 · 룰셋 — 실수의 싹을 자르는 자리

대상삭제 금지force push 금지PR 필수필수 검사
main✓✓✓ + Code Ownersshared · strict
dev✓✓✓shared
part/**✓✓✓shared
feat/**————
⚠ 접두사를 섞지 마라. 통합 브랜치는 part/, 임시 브랜치는 feat/ 다. 둘 다 feat/ 로 두면 룰셋이 구분하지 못해 임시 브랜치까지 force push 가 막히거나 통합 브랜치가 삭제 가능해진다.

⚠ dev 브랜치가 있으면 dev/무엇은 ref 충돌로 만들 수 없다. part 라는 이름의 브랜치를 만들지 마라.

5 · 막히면

상황대응
CI 빨간불실패 메시지를 끝까지 읽는다. 고치는 법이 그 안에 있다
uv.lock 충돌git checkout --theirs uv.lock && uv lock — 손으로 풀지 않는다
web/data 충돌git checkout --theirs web/data/ 후 재생성. 생성물이다
내 PR 을 내가 승인 못 함정상이다. 같은 팀원에게 승인 요청
main 에 잘못 머지됨GitHub Revert 버튼. force push 를 쓰지 않는다
브랜치 실수로 지움룰셋이 막는다. feat/** 이면 git reflog
★ 클론 후 딱 한 번. git config core.hooksPath .githooks
이거 빠지면 커밋 시점 검사가 안 돌고 CI 에서 뒤늦게 잡힌다. 그때는 이미 히스토리에 박혀 있다.
