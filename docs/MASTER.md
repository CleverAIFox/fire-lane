## 3. 이 프로젝트가 발견한 것

### 3-1. "222구간"은 근거가 없었다

기존 문서의 세그먼트 수를 검증한 결과 출처를 찾지 못했다.
정식 행정경계로 재산출하여 **641**로 확정했다.

```
도로명주소 도로구간   206
실폭도로              219
노딩 후 세그먼트      641   ← 판정 단위
```

### 3-2. 도로명주소는 위상이 보장되지 않는다

원본은 "도로명 하나 = 선 하나"라 교차로에서 분할되지 않는다.
노딩 후에도 밀리미터 단위 좌표 오차로 구간이 분리된다(**T자 접합**).

| 처리 | 연결요소 | 최대요소 연장비 |
|---|---:|---:|
| 원본 | 40 | 93.29% |
| `set_precision(0.5)` | 22 | 97.74% |
| **끝점 투영 스냅 0.5m** | **6** | **99.76%** |

잔여 5구간(77m)은 알고리즘 한계가 아니라 **도로명 미부여 구간**이다.
그중 3곳이 관리폭 1.0~1.5m로 소방차 진입이 원천 불가하다.
**데이터의 공백 자체가 위험구간 지표다.**

### 3-3. `ROAD_BT`는 쓰면 안 된다

도로대장의 명목 폭은 **171구간(84%)에서 실측 트랜섹트보다 넓다.**
중앙 차이 +1.00m. 못 지나가는 길을 지나간다고 판정하는 방향이다.

### 3-4. 폭은 하나로 못 정한다

| 이름 | 데이터 | 성격 |
|---|---|---|
| 노면폭 하한 | 실폭도로 폴리곤 | 확실히 비어 있는 폭 |
| 담~담 상한 | 건물 폴리곤 | 물리적 최대 통로폭 |

담~담이 전 구간에서 넓고 중앙 차이 **+2.08m**. 그 사이에
전신주·화분·실외기·계단·주차 차량이 들어 있다.
**밴드를 좁히는 것이 영상판정과 실측의 역할이다.**

### 3-5. ★ 골목의 64%는 영상판정이 불가능하다

CCTV 유효범위를 25m로 잡으면(25m 초과 시 호모그래피 오차 급증):

```
CCTV 유효범위 안         229 / 641  (36%)
CCTV 거리 중앙값          38.6m
최대                      129m
영상판정 불가 구간         195개 · 6,745m (전체 연장의 28%)
```

**영상 기반 진입 판정 시스템을 만들어도 골목의 64%에는 적용할 수 없다.
알고리즘의 한계가 아니라 인프라의 한계다.**

완화 요소: 영상판정 불가 구간이 담당하는 소방 통행량은 **11%**다.
주요 동선에는 대체로 CCTV가 있다.

### 3-6. 출동은 소방서가 아니라 119안전센터에서 나간다

대인(서 1.0km) · 지산(동 1.2km). 둘 다 동명동 밖이다.

```
동 경계 진입점                60곳
실사용 진입점                 23곳
출동 통행의 80%를 담당         5곳
출동 통행의 50%를 담당         2곳
```

**진입점 5곳에 대책을 집중하면 출동의 80%가 개선된다.**

### 3-7. 소화전은 동명동에 1개뿐이다

동부소방서 관할 588개 중 공개된 것이 **31개(5%)**, 그중 동명동이 1개.
데이터 공백 자체가 결과다.

### 3-8. 런타임 프루닝은 폭이 아니라 경로로 한다

정적 폭 기준으로는 61%가 영상판정 대상으로 남는다(동명동이 원래 좁다).
반면 실제 최단경로에 등장하는 엣지는:

```
1회 이상 사용        665 / 4,227  (15.7%)
통행량 80% 담당      177개  (4.2%)
통행량 50% 담당       71개  (1.7%)
```

**71개 엣지가 출동 통행의 절반을 처리한다.** 여기부터 영상판정을 걸면 된다.

## 4. 외부 검증 — 소방서 지정 구간과의 대조

동부소방서 「소방통로확보대상 지역 현황」(2025-07-31, 20구간 7,120m 3,452세대)의
기록 폭과 우리 산출값을 비교했다.

| 도로명 | 소방서 | 우리(중앙) | 편차 |
|---|---:|---:|---:|
| 중앙로272번길 | 5m | 5.33m | **+0.33** |
| 동명로20번길 | 5m | 4.70m | **-0.30** |
| 동계로9번길 | 6m | 7.34m | +1.34 |
| 필문대로289번길 | 8m | 2.00m | -6.00 |

**동명동 2건이 각각 -0.30m, +1.34m.** 실측 없이 얻은 첫 외부 검증이다.

`필문대로289번길`의 -6.00m는 산출 오류가 아니라 매칭 한계다.
소방서 데이터에 좌표가 없어 도로명 전체(대로 구간 포함)를 잡았다.
정밀 대조에는 구간 좌표가 필요하며 D-30 인터뷰 요청 항목이다.

> 8/9에 "미연결 파편"으로 분류했던 **동명로20번길이 실제 소방서 지정 구간**이었다.
> 데이터 결함으로 본 곳이 위험구간이다.

## 7. 남은 일

```
1. node_link + turn_restriction 투입     A* 필수. 이미 보유
2. A* 비용함수 설계                      거리 + 폭 + 통행제한 ∞ + 경사
3. 영상판정(호모그래피) 모듈 연결         needs_cv 72구간
4. D-25 레이저 실측                       width_verified: false → true
5. D-30 인터뷰                            소화전 좌표 + 소방통로 구간 좌표
6. 5m DEM 신청
```

**1번이 먼저다.** 새 데이터 없이 되고, 이것 없이 A*를 만들면 역주행 경로가 나온다.

- **폭 실측 0건.** 8/6 답사는 GPS 미기록으로 무효. 실폭도로 1.76m vs
  수치지도 3.86m 중 무엇이 맞는지 미판정. 그때까지 좁은 쪽으로 보수적으로 간다.
- **CCTV 25m**는 잠정값이다. D-25 실측 검증 대상.
  `segments.py`의 `CCTV_RANGE` 한 줄이며 바꾸면 전체가 재계산된다.
- `midpoint_fallback` 98개, `inherited` 67개는 정상 산출이 아니다.
  결과 해석 시 구분할 것.

## 9. 이 프로젝트의 성격

숫자를 만들어내는 것이 아니라 **어디까지 알 수 있고 어디부터 모르는지를 긋는 것**이다.

- 골목의 42%는 도면만으로 판정이 안 된다 → 주황으로 표시한다
- 그중 다시 64%는 CCTV가 없어 영상판정도 안 된다 → 회색으로 표시한다
- 폭 값은 실측 전이다 → 화면 상단에 상시 경고한다

**모르는 것을 모른다고 표시하는 것**이 이 지도의 설계 원칙이다.
전부 초록으로 칠하면 첫 질문에 무너진다.
