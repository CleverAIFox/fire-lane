## 1. GIS 파트의 경계선 ★ 먼저 합의할 것

혼란의 원인이 여기 있었다. **정적 GIS와 실시간 비전은 만나지 않는다.**

```
GIS(정적)                        비전(실시간)
─────────────────────           ─────────────────────
도로폭 → 1차 분류                CCTV/촬영 → 호모그래피
      → GRAY 판정                        → 통행폭
      → 경로탐색 가중치                  → 차량 점유

입력: 국가 공간정보              입력: 카메라 높이 or 지면 규격물
```

**도로폭은 호모그래피에 들어가지 않는다.** 폭을 쓰려면 화면에서 연석 두 점을 먼저 찍어야 하는데 그게 곧 수동 클릭이고, 폭은 스칼라 1개(2점)라 8자유도인 H를 못 채운다.

따라서 GIS 파트가 정확도를 올리는 이유는 다음 셋뿐이다.

1. **1차 분류** — 어느 골목을 관측 대상으로 삼을지
2. **GRAY 62구간 판정** — CCTV가 없어 호모그래피가 원천 불가. 도로폭이 유일한 근거
3. **경로탐색** — RED 55개를 그래프에서 제외. 틀리면 소방차를 못 가는 길로 보낸다

**2번이 가장 크다.** 전체 222구간 중 62개(28%)가 여기 해당한다.

## 2. 단계별 계획

### Phase 1 — 기반 완성 (다음 주)

| # | 작업 | 산출물 |
|---|---|---|
| 1-1 | `road_width.csv` → `road_segment_master` 병합 | 갱신된 GeoJSON |
| 1-2 | `road_lt` 재계산 (지오메트리 기반) | 경로탐색용 정확한 길이 |
| 1-3 | 노드·링크 그래프 구축 (networkx) | `road_graph.pkl` |
| 1-4 | 다익스트라 구현 + 1·2·3순위 경로 | `route.py` |
| 1-5 | 지도 UI 갱신 (새 폭·새 판정 반영) | `dongmyeong_map.html` |

**1-2를 빼먹지 말 것.** `road_lt`는 222행 중 59행이 클리핑 전 원본 도로 전체 연장을 갖고 있어 최대 5.5배 과대다. 이걸 엣지 가중치로 쓰면 필문대로 25m 조각이 4200m로 계산돼 다익스트라가 간선도로를 무조건 회피한다.

### 가중치 설계

```
cost = length_m × (1 + α·판정페널티 + β·점유위험도)

length_m     지오메트리 재계산값
판정페널티   RED=∞ / YELLOW=실측기반 / BLUE=0 / GRAY=0.5(불확실)
점유위험도   단속밀도(건/100m/년) 0~1 정규화
```

**덧셈이 아니라 곱셈.** 덧셈이면 짧은 위험구간과 긴 안전구간의 비교가 왜곡된다.

### Phase 2 — GRAY 구간 대책 (다음 주 후반)

CCTV가 없는 62구간을 "판정 불가"로 두지 않는다.

| 근거 | 데이터 | 상태 |
|---|---|---|
| 정적 폭 | `width_min_m` | ✅ 확보 |
| 상습 점유 확률 | 단속 이력 3,228건 | ✅ 확보 |
| 고정 장애물 | 전봇대·쓰레기통 (구청 협조) | ❌ 요청 필요 |

```
GRAY 위험도 = f(width_min_m, 단속밀도, 고정장애물 수)
```

**단속 데이터는 시간대 가중치로 쓰지 말 것.** 14시가 전체의 38%인데 이는 주차 패턴이 아니라 단속반 순찰 시각이다. 도로별 상대 비교(사전확률)로만 사용한다.

### Phase 3 — DL 도입 ★ AI 비중 확보

현재 프로젝트의 AI 비중이 부족하다는 지적이 있었다. 호모그래피(기하학)와 다익스트라(알고리즘)는 AI가 아니다. GIS 파트에서 만들 수 있는 AI는 다음 두 가지다.

#### 3-A. 항공영상 도로 세그멘테이션

```
입력   정사영상 GeoTIFF (EPSG:5186, 0.25m/px)
라벨   수치지도 도로경계면을 래스터화 → 학습 라벨 무료 확보
모델   SAM zero-shot → 부족하면 U-Net/SegFormer 파인튜닝
출력   도로 마스크 → distance transform → 폭
```

**라벨링 비용이 0이다.** 수치지도 폴리곤이 곧 정답 마스크다(weak supervision).

**단, 우선순위는 낮다.** GSD 0.25m 기준 이론 한계가 ±0.5m로, 이미 확보한 수치지도(1:5,000)보다 나빠진다. 12cm급 도시지역 영상을 확보하면 재검토.

**진짜 가치는 확장성이다.** 동명동에서 학습한 모델을 광주 전역·타 도시에 적용하면 수치지도가 없는 지역도 커버된다. 발표에서 "우리 시스템은 다른 도시로 확장 가능하다"의 근거가 된다.

> 시도 기록: 색 임계값 및 시드 기반 영역확장은 모두 실패했다(마스크가 화면의 92.9%까지 번짐). 주차 차량·그림자 때문에 색 분포만으로 분리 불가. 학습 기반 모델이 필수다.

#### 3-B. 소방관 선호 경로 학습 ★ 차별점

> "프로그램은 룰 베이스로 다 짤 수 있지만 인간의 감은 못 짠다. 인공지능은 그 감을 흉내낼 수 있다." — 강사

지금 설계는 최단거리 다익스트라라 **일반 내비게이션과 다르지 않다.** 소방관이 실제로 선호하는 경로를 학습하면 그것이 AI 프로젝트로서의 차별점이 된다.

```
1. 인터뷰로 선호 요소 수집 (경사, 회전 반경, 야간 시야, 주차 밀집도…)
2. 각 요소를 특징 벡터로 인코딩
3. 선호 경로 vs 최단 경로 쌍으로 학습 (Learning to Rank / IRL)
4. 학습된 비용함수를 다익스트라 가중치에 주입
```

**인터뷰가 선행 조건이다(P-22).** 소방서 인터뷰를 못 잡으면 이 트랙 전체가 막힌다.

## 3. 우선순위

```
1순위  Phase 1 (1-2 → 1-3 → 1-4)     경로탐색 없으면 프로젝트가 반쪽
2순위  Phase 2                        GRAY 62개는 발표 방어 논리
3순위  Phase 3-B (인터뷰 후)          AI 차별점
4순위  Phase 3-A                      확장성 논거. 정밀도 이득은 없음
5순위  Phase 4                        마지막
```

**3-A를 1순위로 두지 말 것.** DL이 화려해 보이지만 지금 소스보다 정밀도가 낮다. AI 비중은 3-B로 채우는 게 맞고, 3-A는 "확장성" 카드로 쓴다.

## 5. 작업 원칙

1. **모든 수치는 두 방법으로 계산하고 불일치를 먼저 본다.** 수직선법 단독 사용으로 210구간 폭이 절반으로 계산됐고 현장 답사에서야 발견됐다.
2. **물리적으로 말이 안 되는 값은 데이터가 아니라 코드를 의심한다.** "골목 폭 1.3m"가 다수 나왔을 때 즉시 멈췄어야 했다.
3. **약한 통계량을 신뢰하지 않는다.** z-score 3.5의 상관 피크는 틀린 답이었고 육안 오버레이로 기각됐다.
4. **실측 지점은 GPS 좌표를 반드시 기록한다.** 기록하지 않아 8/6 실측이 지점 대조에 쓰이지 못했다.
