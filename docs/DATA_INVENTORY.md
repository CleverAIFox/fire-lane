## 3. 오늘 확인된 것 — 기존 문서와 어긋나는 부분

### ★ 3-1. 도로구간이 교차로에서 안 끊겨 있다 (D-05)

```
도로명주소 도로구간   교차 노드    19개 / 미분할 접점 2,338개   ← 그래프 성립 불가
표준노드링크         교차 노드   452개 / 미분할 접점     7개   ← 정상
```

도로명주소는 "도로명 하나 = 선 하나"라 제봉로가 중앙로를 가로질러도 통짜 한 줄이다.
**노딩 없이 networkx에 넣으면 다익스트라가 "경로 없음"을 뱉는다. 코드 문제가 아니다.**

노딩 결과(bbox 기준): `1,812 → 4,336 세그먼트 / 노드 3,702 / 연결요소 338개(최대 80%)`

> **"222구간"의 근거를 찾지 못했다.** 정식 행정경계 확보 후 재산출하여 전 문서를 교체할 것.

### ★ 3-2. 도로폭 소스 3종이 서로 다른 값을 준다

동일 구간(`ROAD_BT`=2.0)을 세 방법으로 측정:

| 소스 | 폭 |
|---|---:|
| `ROAD_BT` (명목값) | 2.00 |
| 실폭도로 `TL_SPRD_RW` 트랜섹트 | 1.76 |
| 수치지도 `NF_A_A01000` 트랜섹트 | 3.86 |

**`ROAD_BT` 사용 금지 확정.** 정수 비율 90%, 값의 30%가 정확히 2.0에 몰려 있다.
실측값이 아니라 도로명 부여 기준의 명목 관리 폭이다.
게다가 실제보다 **크게** 나오는 방향이라 D-03의 미탐(막혔는데 통과 판정) 쪽으로 편향된다.
가장 위험한 방향이다.

수치지도가 실폭도로보다 넓게 나오는 이유는 대상이 다르기 때문이다
(수치지도=포장면 전체, 실폭도로=도로명주소 관리 실폭).
**어느 쪽이 맞는지는 현장 실측만이 판정할 수 있다.**
8/6 실측은 GPS 미기록으로 무효 처리된 상태이므로, D-25 레이저 거리계 확보 후 재실측이
우선순위 1번인 이유가 이것이다.

## 4. 지도 스택 결정

**MapLibre GL JS + V-World 타일.** Mapbox도 Naver도 아니다.

- MapLibre는 Mapbox GL v1 포크라 기존 `dongmyeong_map.html` 코드가 거의 그대로 붙는다
- V-World가 한국 배경(건물·지명·지적·항공영상)을 국토부 원본으로 제공한다
- Naver의 "한국 로컬 데이터 풍부" 이점이 사라지고, GeoJSON 데이터 기반 스타일링은
  MapLibre가 압도적이다
- 상가 POI는 `poi_store`로 직접 얹으므로 Naver가 필요 없다

`dongmyeong_map_naver.html`은 갱신 중단. 두 벌 유지가 구버전 폭을 물고 있던 원인이다.
