### 1-23. 영상판정 유효거리 실측 설계

★ `MASTER §16-1` 이 광학 계산을 적는다. **여기는 그것을 재는 방법이다.**

**실험**

    한 골목에서 d = 5 · 8 · 12 · 16 · 20 · 25m 지점에 삼각대를 세우고 촬영
    같은 단면을 레이저 거리계로 1회 실측
    → 거리별 오차 곡선 → 0.3m(임계 뒤집힘)를 넘는 d 를 높이별로 확정

높이는 최소 둘(삼각대 1.5m · 연장 3~4m)을 재야 `h` 의 영향이 분리된다.
한 높이만 재면 거리 효과와 높이 효과가 섞인다.

**결과가 나오기 전에는 `CCTV_RANGE = 25.0` 을 유지한다.**

### 1-24. 촬영 계획이 높이에서 갈린다

```
구간 길이 중앙값 36.3m
h = 1.5m (유효 11.0m)  →  구간당 3~4회
h = 4.0m (유효 17.5m)  →  구간당 2~3회
```

1,101구간이면 전자는 감당이 안 된다. **높이를 올리는 것이 곧 촬영 횟수를
줄이는 것**이고, 그것이 장비 판단의 근거다.

### 1-25. ⚠ 인터뷰에 A* 를 걸지 마라

선호도 기반 피처는 인터뷰가 있어야 **가중치**를 정할 수 있다. 그러나 **구조**는
인터뷰 없이 정해진다 — 거리 · 폭 · 통행제한 · 내륜차는 전부 보유 데이터로 된다.
인터뷰를 전제로 설계하면 무산될 때 A* 전체가 뜬다. 인터뷰는 "있으면 좋은 것"이지
"없으면 못 하는 것"이 되면 안 된다.

## 2. 아키텍처 · 모듈 경계

### 2-1. GIS ↔ 비전 — 접점은 정확히 두 개 📄

```
GIS ──[관측점 선정]──▶ 비전      어느 골목의 어느 지점을 찍을지 GIS 가 정한다
GIS ◀──[판정 결과]──── 비전      seg_uid + 통행폭 + 시각
```

**반대 방향이 없다는 것이 핵심이다.** GIS 도로폭은 호모그래피 입력으로 들어가지
않는다. 반환 스키마의 정본은 `MASTER §19` 다.

### 2-2. 정적 계층 대 동적 계층 📄

| 계층 | 갱신 주기 | 내용 |
|---|---|---|
| 정적 | 월 1회 | 도형 · `width_min_m` · `verdict` · `cctv_dist_m` |
| 동적 | 수 초~분 | `current_status` 컬럼 **하나만** |

"동적"은 DB 엔진 성질이 아니라 **클라이언트 폴링 루프 + 얇은 상태 컬럼**에서
나온다. 무거운 공간조인은 정적 계층에서만 돌린다.

### 2-3. 서빙 원칙 📄

FE 든 QGIS 든 **`serving` 스키마 하나만 보고 GeoJSON 을 받는다.** 판정 로직을
프론트에서 재계산하게 하면 안 된다. 로직은 백엔드에 하나, 소비자는 여럿.

## 3. 폭 산출 · 판정

산출 방식 자체는 구현이 끝났고 정본은 `MASTER §3` 이다. 여기에는 남은 것만 둔다.

### 3-1. 남은 것 🟡

```
width_cov 0.5 미만 4구간    채택 소스가 구간의 절반도 못 덮었다. D-25 실측 1순위
wmax 교차로 누출            벽~벽이 46~57m 로 샌다. width_max_m 필드 신뢰 불가
소방서 대조 잔여 편차        필문대로289번길 -3.51 · 제봉로184번길 +2.02
road_side 의미               측도 구분이 아님만 확인됨
```

### 3-2. 계산 방식 교차검증 — 미구현 🟡

폭 계산은 **두 가지 방법(법선 트랜섹트 / 거리변환)으로 하고 불일치 구간을 먼저
본다.** 단일 방법만 쓰면 인접 폴리곤 경계에서 교차선이 분할돼 폭이 절반 이하로
계산되는 사고가 난다 — 실제로 210구간에서 났고 현장 답사에서야 발견됐다.

거리변환 교차검증은 아직 없다. 정사영상 388타일을 활용한 전수 검증이 다음 후보다.

### 3-3. 판정 오류의 비대칭 📄

| 오류 | 결과 | 비용 |
|---|---|---|
| **미탐** (막혔는데 통과 가능 판정) | 소방차가 골목에 갇힌다 | **치명적** |
| **오탐** (통과 가능한데 막혔다고 판정) | 조금 돌아간다 | 경미 |

**두 오류의 비용이 100배 차이다. 임계값을 대칭으로 두면 안 된다.**
이것이 발표 방어 논리로 최강이다 — "틀릴 수 있다. 그래서 틀리는 방향을 설계했다."

⏳ 여유값 0.5m 는 실운전자 인터뷰로 검증한다(§9-1 #4).

### 3-4. 인도 포함 문제 📄

수치지형도 도로경계면은 포장면 기준이라 담장 안쪽이 안 들어간다. 동명동 도로
대부분이 좁아 인도가 물리적으로 존재할 수 없고, 인도가 있을 수 있는 5~8m
구간은 인도 2m 를 잘못 포함해도 잔여 폭이 통과선을 넘어 **판정이 뒤집히지 않는다.**

### 3-5. 근거 없는 상수에 근거 붙이기 🔴

목록과 현재 값은 `MASTER §16-2` 가 든다. 여기서는 **누가 언제 붙이는가**만 다룬다.
`CCTV_RANGE` 는 §1-23 실측에 걸려 있고, `WMAX_CAP` 은 주석과 코드가 어긋나
있으므로 그 불일치부터 정리한다. 나머지 둘은 담당이 없다.

## 4. 그래프 · 경로탐색

### 4-1. 가중치 설계 📄

**곱셈형으로 확정.**

```
cost = length_m × (1 + α·판정페널티 + β·점유위험도)
```

덧셈이면 짧은 위험구간과 긴 안전구간의 비교가 왜곡된다.

| 판정 | 페널티 |
|---|---|
| 통행 불가 | ∞ |
| 판정 보류 | 실측 기반 |
| 영상판정 불가 | 0.5 (불확실) |
| 통행 가능 | 0 |

점유위험도 = 단속밀도(건/100m) 정규화값.

⚠ **길이는 지오메트리에서 재계산한다.** `ROAD_LT`(도로 연장)는 **클리핑 전
원본 도로 전체 길이**를 갖고 있다. 필문대로 25m 조각에 4,200m 가 기재되는
식이다. **엣지 가중치에 절대 쓰지 않는다.**

### 4-2. A* 대 다익스트라 📄

**둘 다 한다. 비용이 0이다.** 이 규모에서 성능 차이는 무의미하다. A* 를 쓰는
이유는 속도가 아니라 발표 논거다 — "광주 전역 확장 시 탐색 공간이 커지므로
휴리스틱이 필요하다". 실행시간 비교 그래프 한 장이면 된다.

⚠ **휴리스틱이 실제 비용을 넘으면 최적해가 깨진다.** cost 에 페널티 곱셈이
들어가므로 직선거리를 그대로 쓰면 안 되고 **최소 배율로 나눠야** 한다.
여기 틀리면 A* 가 다익스트라와 다른 답을 낸다.

★ 목적지가 다수인 현재 산출(안전센터 → 전 노드)에는 A* 의 이점이 없다.
A* 가 맞는 자리는 출발 1 → 도착 1 인 네비게이션 쪽이다(MASTER §3-10).

### 4-3. 체크포인트를 엣지 속성으로 📄

소화전 · CCTV · 단속밀도를 **엣지 속성**으로 붙인다. 노드가 아니다.
경로 산출 후 "이 경로상 소화전 3개 경유"를 바로 뽑을 수 있다.

### 4-4. TMAP · 카카오 — 병합이 아니라 병렬 비교 📄

```
1. 같은 출발-도착지로 외부 API 호출  → 추천 경로 (교통체증만 고려)
2. 우리 다익스트라 호출              → 우리 경로 (통과 가능성 반영)
3. 두 결과를 나란히 제시
```

외부 API 는 링크별 혼잡도를 낱개 조회하는 구조가 아니라 완성된 경로를 반환하는
구조라, 우리 그래프의 모든 간선에 혼잡도를 채우는 방식이 성립하지 않는다.
포지셔닝과도 맞는다 — **차별점은 "그쪽이 모르는 걸 우리는 안다" 하나에 집중한다.**

### 4-5. 미결정 🟡

| 항목 | 선택지 | 비고 |
|---|---|---|
| **그래프 방향성** | 무향 + "긴급차량 예외" 명시 ← 추천 / 유향 + 역주행 페널티 | **결정 안 하면 코드가 두 번 갈아엎힌다**. `D-07` |
| **회전 판정 적용 범위** | 시연 경로 코너만 검증 ← 추천 / 전 구간 | 전 구간 적용 시 골목 대부분 탈락 → 그래프 붕괴. `D-08` |
| 클리핑 범위 확장 | 소방서~동명동 진입 경로 포함 | 미착수 |

#### 회전 반경 기준 📄

**폭 3m 골목이라도 직각 코너면 소방차는 못 돈다.** 내륜차 때문이다.
계산식과 값은 `MASTER §3-13` 이 든다.

| 상황 | 기준 |
|---|---|
| 직진 | 유효 폭 3m 이상 |
| **회전(코너)** | 회전반경 차량 중심 10m + 곡선부 폭 4~6m |
| 진입 불가 | 폭 2m 이하 |

**설계 원칙** — `간선 = 직진 폭 판정 / 노드 = 회전 가능 판정. 둘 다 통과해야
유효 경로.`

⚠ 출처가 전부 블로그·기술사 정리다. 「소방청 건축위원회 표준 가이드라인
2021.10」 원문 확보가 필요하다(§9-1 #10).

발표 문구 — "회전 제약을 모델에 포함했고 시연 경로는 검증했다. 전 구간 적용은
코너 실측 데이터 확보 후."

### 4-6. 일방통행 · 회전제한 투입 📄

데이터는 이미 파이프라인에 있다. **그래프에 투입만 하면 된다.**

## 5. 비전 파트

### 5-1. 캘리브레이션 ≠ 호모그래피 📄

| | 캘리브레이션 | 호모그래피 |
|---|---|---|
| 대상 | 카메라 내부(렌즈) | 카메라와 지면의 관계 |
| 구하는 것 | 초점거리 · 주점 · 왜곡계수 | 3×3 행렬 H |
| 방식 | 체커보드 20여 장 | 대응점 4쌍 이상 |
| 주기 | 카메라·렌즈당 1회 | **카메라를 옮길 때마다** |

**순서 — 렌즈 왜곡 보정 → 대응점 → 호모그래피.** 왜곡을 먼저 펴지 않으면 H 를
잘 구해도 화면 가장자리에서 틀어진다. **대응점은 4쌍이 최소조건이지 권장값이
아니다.** 실무는 6~8쌍 + RANSAC.

### 5-2. 대응점을 지면에 고정한다 📄

**카메라 위치·높이·각도를 재현하려는 시도를 포기한다.** CCTV 가 아니라 CCTV
모사이고, 삼각대를 매번 들고 나가므로 카메라는 전혀 고정이 아니다.

```
관측점당 1회 (영구)   지면 영구 지물 4~6개의 실세계 상대좌표 실측
매 세션              같은 지물의 이미지 좌표만 다시 얻음 → H 재계산
```

기준 지물 후보 — 맨홀 뚜껑 모서리, 보도블록 줄눈 교차점, 전주 밑동, 연석 이음매,
배수구 격자.

**카메라가 어디 서 있든 같은 지면 점들이 프레임에 보이기만 하면 H 가 매번
정확히 나온다.** "매번 동일 위치에서 찍어야 한다"는 제약이 통째로 사라진다.
2회차부터는 1회차 기준 이미지와 특징점 매칭으로 자동 정합한다.

이 결정이 §6-2 관측점 개체화를 강제한다.

### 5-3. 오차 구조 📄

초점거리 f(px), 카메라 높이 h, 대상 거리 d 일 때 1픽셀 오차의 실제 크기다.

```
깊이 방향   d² / (f · h)      ← 거리의 제곱. 급격히 나빠진다
가로 방향   d / f             ← 거리에 비례. 완만하다
```

| 거리 | 깊이 1px | 가로 1px |
|---|---|---|
| 10 m | 0.067 m | 0.010 m |
| 20 m | 0.27 m | 0.020 m |
| 30 m | 0.60 m | 0.030 m |

> **골목을 따라 정면으로 촬영한다. 옆에서 가로지르며 찍지 않는다.**

정면이면 도로 폭이 **가로 방향**이 되어 15m 앞 차량을 5px 틀려도 오차가
0.08m 다. 옆에서 찍으면 같은 5px 이 1m 이상 벌어진다. 분모에 h 가 있으므로
**카메라를 높일수록 깊이 오차가 줄어든다.**

| 오차 요인 | 영향 | 대응 |
|---|---|---|
| 대응점 실측 오차 | 최대 | 레이저 거리계 |
| 대응점 배치 | 큼 | 화면 넓게 분산. 한 줄 배열 금지 |
| 지면 평탄 가정 위반 | 큼 | 경사 골목 회피. 관측점 선정 시 고려 |
| 렌즈 왜곡 미보정 | 중 | 체커보드 선행 |
| 카메라 높이 오차 | 중 | 삼각대 고정이면 설정값이라 작다 |

### 5-4. 촬영 체크리스트 📄

### 5-5. 유효폭 계산 📄

**뺄셈 방식("GIS 도로폭 − 감지 차폭") 미채택.** 오차가 두 군데에서 이중
누적된다. 대신 **호모그래피 변환 좌표계 위에서 세그멘테이션 결과를 직접
측정**한다.

- YOLO11-seg. COCO `{2:car, 3:motorcycle, 5:bus, 7:truck}`
- **세그멘테이션 필수.** bbox 는 비스듬한 차량에서 폭을 크게 과대추정한다
- **바닥 접지선 기준** — 마스크 최하단 행의 좌·우 끝
- 한계 — 사이드미러 등 뜬 부분은 못 잡는다. 안전마진이 흡수하도록 설계한다

집계 규칙과 함정은 `MASTER §19-5` 가 정본이다.

### 5-6. DL 투입 지점 🟡

단일 사전학습 모델 하나로는 "가져다 쓴 것"이라 주인공이 못 된다.

| 우선 | 항목 | 억지 없음 정도 |
|---|---|---|
| 1 | **프라이버시 파이프라인** (번호판·얼굴 마스킹) | 없으면 프로젝트가 법적으로 성립 안 함 |
| 2 | **주정차 대 주행 판별** (시간축) | 아키텍처가 이걸 요구한다 |
| 3 | **야간 강건성** (저조도 향상·도메인 적응) | 실제 문제에서 출발 |
| 4 | 소방관 선호 경로 학습 | 인터뷰 성공이 선행 조건. 리스크 큼 |

#### 프라이버시는 엣지에서

**원본이 서버로 넘어가는 순간 개인정보를 "수집"한 것이 된다.** 엣지에서 마스킹
후 전송하면 서버는 애초에 개인정보를 보유하지 않는다. 발표에서 이 논리 하나로
개인정보 질문을 막을 수 있다.

#### 주정차 판별은 시간축으로

**가상 중앙선은 쓰지 않는다.** 골목엔 중앙선 개념이 없다. 정답은 **연속
프레임에서 정지 = 주차**다. 이것이 아키텍처를 강제한다 — **mock 서버가 단일
이미지가 아니라 프레임 시퀀스를 반환해야 한다.**

```
관측점에서 삼각대 고정 → 30초~1분 동영상 1개
→ 프레임 추출 + 타임스탬프 → mock 서버가 순서대로 반환
```

주행 차량은 5초면 화면을 벗어난다. 30초면 충분하다. **"24시간 연속 관측
불가"와 "시퀀스 확보 불가"를 혼동하지 않는다.** 전자만 사실이다.

#### 답사 1회로 셋을 해결한다

**같은 관측점을 오전·오후·야간 3회 촬영한다.** "14시 통과 가능 / 19시 불가"는
서비스 필요성 최강 소재이고, 관측 신선도(§7-3)와 야간 성능 데이터가 함께 나온다.

### 5-7. 상습주차 추정 모델 📄

단속 이력이 레이블이다.

```
학습   도면 특징(도로 폭 · 벽 사이 폭 · 상가 밀도 · 건물 층수 ·
       주차장까지 거리 · 도로 위계 · 출입구 밀도) → 단속 발생 빈도
적용   CCTV 없는 구간의 상습도 예측
검증   답사 촬영 · 소방서 인터뷰
```

⚠ **시간대는 쓸 수 없다.** 14시가 39.1% 로 입력 기본값이 오염돼 있다.
구간별 빈도만 쓴다. **출동 시점의 상태가 아니라 사전 위험도다.**

⚠ **단속 이력에 좌표가 없다.** `위반장소명` 이 도로명주소이므로 도로명으로
조인한다. 단 절반이 랜드마크 명칭이라 필터가 필요하다.

## 6. 실측

### 6-1. 실측 프로토콜 📄

**2026-08-06 답사는 GPS 를 기록하지 않아 대조에 쓸 수 없다.** 세그먼트
중심선과 최대 23m 어긋났고 그날 산출된 소스별 오차 수치는 전부 무효다.
같은 실수를 반복하지 않기 위한 필수 항목이다.

```
1. seg_uid + 관측점 ID
2. ★ 기준 지물 서술 — "서쪽 끝에서 세 번째 맨홀 중심"
3. GPS 좌표 (보조. 지물이 우선)
4. 기준 사진 (기준 지물이 프레임에 보이게)
5. 측정 종류 — 벽~벽 / 연석~연석 / 통행폭 / 코너폭
6. 시각 · 날씨 · 조도
7. 삼각대 높이 · 방위 · 촬영 설정
```

#### ⚠ GPS 로는 지점 특정이 안 된다

도심 골목 폰 GPS 오차 **5~15m**, 골목 폭 **3m**.

| GPS 로 되는 것 | 안 되는 것 |
|---|---|
| 어느 세그먼트 위인가 | 세그먼트 내 어느 지점인가 |

**지점 특정의 해법은 지물 기준이다.** 기준 지물을 적고 그것이 프레임에 보이게
찍으면 재방문 시 재현된다.

#### 장비 📄

- **레이저 거리계** (20~30m급) — 확보 완료
- 30m 줄자 (백업). ⚠ 줄자 U자 처짐 오차는 5m 구간에서 수십 cm 다.
  **안전마진(0.5m)보다 오차가 크면 실측이 무의미하다**
- 반사 대상이 없을 때는 A4 클립보드·흰 폼보드를 팀원이 들고 선다
- **차량 간 거리는 차체가 아니라 지면 마킹 간 거리를 잰다.** 곡면이라 레이저가 튄다

### 6-2. 관측점을 GIS 1급 개체로 📄

지금 설계에 **"카메라를 세우는 지점"이라는 실체가 없다.**

```json
{
  "obs_id": "OBS-001",
  "seg_uid": "DM-192942-283921-YM7N",
  "geom": [x, y],
  "landmark_desc": "장동로 서쪽 끝에서 세 번째 맨홀",
  "ref_points": [
    {"id": "R1", "desc": "맨홀 북동 모서리",   "local_xy": [0.0, 0.0]},
    {"id": "R2", "desc": "보도블록 줄눈 교차", "local_xy": [2.4, 0.0]}
  ],
  "ref_image": "obs001_ref_20260810.jpg",
  "sessions": [
    {"at": "2026-08-10T09:30", "video": "...", "H": [[]], "illum": "day"},
    {"at": "2026-08-10T19:40", "video": "...", "H": [[]], "illum": "night"}

따라오는 것 — 세션 간 H 재계산 / 시간대별 통행폭 비교 / **관측 커버리지
레이어**(회색 구간 중 어디를 실제로 덮었는지) / 발표에서 정량 제시.

**관측점으로 CCTV 좌표를 그대로 쓰지 않는다.** 시나리오 경로 위에서 골라야 한다.

#### 실측 지점 선정 — 데이터로 뽑는다

손으로 고르지 않는다. 손으로 고르면 근거가 안 남는다.

| 묶음 | 기준 | 산출 |
|---|---|---|
| 촬영 | `needs_cv` + `cctv_dist_m` ≤ 25 + `route_usage` 상위 | `tools/desk_check.py --track shoot` |
| 폭 검증 | `width_disagree_m` 상위 | `--track disagree` |
| 결손 확인 | `width_max_m` 결손 잔여 64건 | `--track wmax` |
| 형상 확인 | 도로경계 폴리곤 밖 37구간 | `uncovered_units.json` |

`width_cov` 가 낮다는 것은 **그 소스가 못 잰 구간이 있는 채로 판정했다**는
뜻이다. 숨기지 않고 필드로 드러냈으니 실측 우선순위로 쓴다.

### 6-3. 실측 보조 앱 📄

**네이티브 앱 금지.** 기존 지도 HTML 에 얹는다.

| # | 기능 |
|---|---|
| 1 | 현재 GPS + 최근접 세그먼트 자동 판별 |
| 2 | 관측점 등록 → 좌표·시각·`seg_uid` 자동 기록 |

**전제** — HTTPS 가 아니면 `navigator.geolocation` 이 동작하지 않는다.

**설계 원칙** — GPS 는 보조다. 가장 중요한 입력은 **기준 지물 서술과 기준
사진**이다.

### 6-4. 호모그래피 기준점 실측 — ArUco 보드 🟡

**배포될 방법은 마커를 쓰지 않는다.** 세그멘테이션이 검출한 도로 경계선을
수치지형도 도로경계 폴리곤에 맞춰 H 를 푼다. CCTV 104지점에 보드를 깔 수는
없으므로 처음부터 이 방법이어야 한다.

문제는 **그 방법의 오차를 아무도 모른다**는 것이다. 지도 기준점으로 H 를 풀고
그 H 로 잰 폭을 지도 폭과 비교하면 순환논증이다. 소방서 7구간에서 이미 겪은
병이다 — **게이트로 쓴 자료는 검증 수단이 아니다.**

**ArUco 보드는 지도 밖에서 온 자다.** 3~5곳에서 한 번 재고 끝낸다.

#### 세 방법을 같은 골목에서 비교한다

```
방법 A   지도 기준점으로 H        ← 배포될 방법
방법 B   ArUco 보드로 H           ← 독립 기준
방법 C   레이저·줄자 실측          ← 절대 기준

|A − C|  배포 방법의 절대 오차     ← 발표에서 말할 숫자
|A − B|  지도 기준점 자체의 오차
|B − C|  보드 방식의 오차. B 가 A 보다 크면 대조 자체가 무의미하다
```

D-25 와 같은 현장·같은 동작이다. **두 번 나가지 않는다.**

#### ⚠ 눕힌 마커는 10m 를 못 넘는다

노면에 눕힌 마커는 얕은 시선각에서 깊이 방향이 짓눌린다.

```
h=1.5m, d=15m → 시선-지면각 5.7° → 깊이 축소율 0.10
150mm 마커 = 가로 32px · 깊이 3px      ArUco 검출 불가
```

인쇄 크기를 키워도 축소율이 그대로 곱해진다. **크기로 못 이긴다.** 실용 한계는
대략 `d < 5~8h` 이며 삼각대 1.5m 면 10m 내외다.

★ 따라서 **근경 10m 는 보드, 원경 10~25m 는 지도**로 나눈다. 원경에서는 골목
양쪽 도로경계선이 평행하다는 것과 그 실간격을 수치지형도에서 읽을 수 있다는
것이 소실점까지 구속한다. 마커보다 조건이 좋다.

#### 보드 사양

| | |
|---|---|
| 재질 | **하드보드지.** 종이가 휘면 평면성이 깨지고 코너가 어긋난다 |
| 크기 | A2 이상. 마커 4개 이상이 한 장에 인쇄된 단일 보드 |
| 인쇄 | **무광.** 코팅·비닐 금지 — 노면 반사광에 마커가 날아간다 |
| 사전 | `cv2.aruco` DICT_4X4_50, 마커 150mm, 간격 인쇄값 기록 |

★ 마커 4장을 흩어 놓고 6거리를 줄자로 재지 않는다. 그러면 ArUco 의 가장 큰
값(기하가 인쇄로 확정됨)을 버리고 측량 공수만 남는다.

#### 현장 절차 — 관측점당 40분

```
1. 삼각대 고정. 높이 기록. 이후 건드리지 않는다
   AE/AF 락 · 손떨림보정 OFF · 표준 1x · 4K
2. 보드를 3 · 5 · 8 · 10 · 12 · 15m 로 옮기며 촬영
   ── 어느 거리에서 검출이 깨지는지 기록한다. 그 값이 이 카메라의 유효거리다
3. 검증점 — 5 · 12 · 20m 노면에 분필 십자. 좌우 폭을 레이저로 실측
   ★ 이 점들은 H 산출에 쓰지 않는다
4. 지도 대응점 — 도로경계 좌우, 교차점, 건물 모서리가 프레임에 보이는지 확인
5. 기준 사진 · 방위 · 시각 · 날씨 · 조도 (§6-1 필수 항목)
```

#### ★ 검증점을 H 산출에서 반드시 뺀다

H 를 푼 점으로 오차를 재면 잔차가 0 이다. 자기 자신에 적합시킨 값이다.
이 조건이 없으면 그 숫자는 소방서 대조와 같은 성질이 된다.

#### 보고 형식

점추정으로 말하지 않는다. 3~5곳은 표본으로 적다.

```
5개 골목 · 검증점 24개 · 중앙 오차 6cm · 최대 14cm · 유효거리 11m
```

표본 수와 최대값을 같이 밝히는 형태만 방어된다.

#### 이 절이 성립하지 않아도 시스템은 돈다

보드가 없으면 "오차가 얼마인지 모른다"가 될 뿐이다. 발표에서 숫자를 말할
것인가 "정확도는 D-25 이후"라고 말할 것인가의 차이이며, 하드보드지 한 장과
반나절의 값이 거기 있다.

### 6-5. 안전 — 타협 대상 아님

- **오전 9~11시 고정.** 8월 광주 오후 아스팔트 답사는 실제로 위험하다
- 야간 답사는 별도 일정
- 도로 한복판 실측 시 **2인 1조, 1명은 차량 감시**

### 6-6. 실측 표본 트랙 — 섞지 마라 🔴

```
A 12구간   width_src × 폭대역 층화 무작위    편향 추정용
B  8구간   임계 근접 + 상대불일치            판정 교정용
C  5구간   단순 무작위 · 봉인                외부 검증용
```

**A 와 B 를 합쳐서 편향을 추정하면 추정치가 망가진다.** B 는 "소스끼리 값이
다른 곳"만 고른 표본이라 그 오차 분포는 전체 분포가 아니다.

★ 불일치 기준은 **절대값이 아니라 상대값(35%)** 이다. 절대 1.0m 로 잡으면
20m 도로의 10% 오차는 통과하고 3m 골목의 10% 오차는 탈락한다.

**C 는 열지 않는다.** 소방서 7구간이 이미 게이트가 되었으므로 현재 외부 검증
수단은 0개이고 C 가 그 자리를 대신한다. 회차마다 2~3구간씩 봉인 몫을 추가하되
분석에는 쓰지 않는다.

### 6-7. 오차를 줄이는 순서 📄

```
1회차   트랙 A 12구간 → 소스별 편향 b, 산포 σ 추정
2회차   그 모델로 트랙 B 를 미리 예측하고 나간다 → 실측과 비교
3회차   안 맞는 구간의 공통점을 찾아 모델 개선
```

**2회차가 핵심이다.** 예측을 적어놓고 재면 맞았는지가 현장에서 갈린다.
오차를 줄이는 것이 아니라 **오차 모델이 맞는지 검증하는 것**이다.

### 6-8. 네이버 지도 준-실측 가능성 🟡

현장 실측 25구간 75점으로 1,101구간을 덮지 못한다. 네이버 지도의 거리 측정
도구를 준-실측으로 쓸 수 있으면 전수 대조가 가능해진다.

표본 46구간을 폭 대역별로 층화해 뽑았다. 판정 임계(3.0 / 7.0m) 근처를 두껍게
하고, 12m 이상은 재봐야 판정이 안 바뀌므로 얇게 한다.

```
tools/naver_check.py    표본 + 봉인
tools/naver_page.py     입력 페이지 (미니맵 · 방위)
tools/naver_join.py     봉인 해제 + 대조
```

**판단 기준**

```
|중앙 편차| < 0.3m · 표준편차 < 0.5m   전수 대조 가능
중앙 편차는 크나 산포가 작다            계통오차. 보정 상수로 잡힌다
산포가 크다                            못 쓴다. 순서형 참고로만
```

★ 어느 쪽이든 레이저 실측을 없애지 않는다. 네이버도 지도이고 우리 소스와 같은
국가 데이터에서 파생됐을 수 있다. **실측 규모가 줄어드는 것이지 없어지는 것이
아니다.**

상태 — 표본 생성 완료. 측정 미착수.

## 7. 시나리오 · 평가

### 7-1. 시나리오를 손으로 고르지 마라 — 그래프에서 역산 📄

```python
for (출발, 도착) in 조합:
    d1 = 최단경로(제약 없음)
    d2 = 최단경로(통행 불가 제외)
    if d2 / d1 > 1.5 and d2 < inf:
        후보에 추가
```

**"우리 시스템이 없었으면 소방차가 갇혔을 출발-도착 쌍"을 자동으로 찾는
것이다.** 시나리오 선정 자체가 GIS 산출물이 되고, "임의로 고른 것 아니냐"는
질문을 막는다.

출발점은 대인·지산 119안전센터다. **선정 조건** — 코너 통과 가능 / CCTV 커버
구간 포함 / 우회로 존재.

### 7-2. 평가지표 — 설계 완료, 산출 미착수 🟡

> **우리 시스템이 잘 작동한다는 걸 무엇으로 증명하나.**

세 회의 연속 미결이었던 이유는 담당자가 없어서가 아니라 **"실측 없이는 정확도를
못 낸다"에 나머지 지표가 전부 묶여 있었기 때문**이다. 갈라 적으니 셋은 지금 낼
수 있는 것이었다.

| ID | 지표 | 지금 | 전건 |
|---|---|---|---|
| E-1 | 진입 실패 회피율 | **가능** | 없음 |
| E-2 | 우회 비용 | **가능** | 없음 |
| E-3 | 판정 가능률 | **값 있음** | 없음 |
| E-4 | 폭 정확도 (MAE) | 불가 | D-25 실측 |
| E-5 | 재현성 게이트 | **가능** | 없음 |

E-4 는 정의만 해둔다. **빈칸으로 두지 말고 "D-25 이후"라고 적는다.** 발표에서
표의 빈칸과 "전건이 이것이다"는 완전히 다르게 읽힌다.

#### 7-2-1. 원칙 셋

**적합과 검증을 섞지 않는다.** 소방서 7구간 대조는 게이트로 썼으므로 외부 검증
수단이 아니다. **이 절의 어떤 지표도 "우리 폭이 정확하다"를 주장하지 않는다.**
주장하는 것은 하나다 — *현행 방식 대비 무엇이 나아지는가*.

**결손은 관대한 쪽으로 해석하지 않는다.** 산출 불가는 **분모에서 빼지 말고
별도 항으로 보고한다.** 못 잰 것을 조용히 지우면 커버리지가 저절로 올라간다.

**지표는 값이 아니라 실행이다.** `data/processed/eval.json` 으로 떨어뜨리고
형식을 다른 대조 산출물과 맞춘다. `tools/baseline.py` 가 실행 간 자동 비교할 수
있어야 한다. **터미널에만 있는 숫자는 소실된다.**

#### 7-2-2. E-1 · 진입 실패 회피율

> 우리 시스템이 없었으면 소방차가 못 가는 길로 안내받았을 비율

```
baseline   거리만으로 최단경로 (현행 내비게이션이 하는 일)
ours       통행 불가 구간을 제외한 최단경로

E-1 = (baseline 경로가 통행 불가 구간을 1개 이상 지나는 쌍) / (전체 쌍)
```

입력 — 출발은 대인·지산 119안전센터 2곳, 도착은 동명동 건물 층화 표본,
그래프는 표준노드링크 + 회전제한이다. 산출기는 §7-1 의 의사코드가 그대로 된다.
**두 작업이 아니라 한 작업이다.**

⚠ 통행 불가 159 는 **하한이다.** 잔여 결손 64건 때문에 E-1 은 과소평가 쪽으로
치우친다. 그 방향을 명시해 보고한다.

#### 7-2-3. E-2 · 우회 비용

```
E-2a  d2/d1 중앙값 · 90퍼센타일       거리 증가율
E-2b  d2 = inf 인 쌍의 수             우회로가 아예 없는 목적지
```

**E-2b 가 본체다.** 증가율은 "조금 돌아간다"로 끝나지만, 도달 불가는 "소방차가
못 간다"다. 발표에서 지도에 찍을 것도 이쪽이다.

⚠ 영상판정 불가 354 를 어느 쪽으로 셀지 정해야 한다. **세 가지 다 낸다** —
낙관(통과 가능 · 하한) · 비관(통과 불가 · 상한) · 현행(지금 지도가 하는 일).
**하나만 내면 고른 이유를 방어해야 하고, 셋을 내면 폭이 논거가 된다.**

⚠ 시간 환산은 하지 않는다. 골목 주행속도 근거가 없다. 거리만 쓴다.

#### 7-2-4. 표본 설계

전수는 계산이 무겁고, 무작위는 "왜 그 쌍이냐"를 못 막는다. **층화한다.**

| 층 | 기준 | 왜 |
|---|---|---|
| A | `route_usage` 상위 | 실제 동선. 579구간이 0 초과 |
| B | `nfa_designated` 인접 | 소방청 지정 기준 충족 구간 |
| C | 영상판정 불가 밀집 | CCTV 사각의 실제 영향 |
| D | 무작위 | 층화가 만든 편향의 대조군 |

D 를 반드시 넣는다. 위험한 곳만 골라 놓고 "위험하다"는 결론을 내면 그것은
지표가 아니라 순환논증이다. 표본 수·시드는 `eval.json` 에 박는다.

#### 7-2-5. E-3 · 판정 가능률

이미 값이 있다. 재산출만 하면 된다.

연장 기준            14,505m / 48,580m  (30%)

답하는 것과 먼저 말하는 것은 다르게 들린다 — *알고리즘의 한계가 아니라
인프라의 한계다.* 완화 항(영상판정 불가 구간이 담당하는 통행량 18%)도 같이 낸다.

#### 7-2-7. E-5 · 재현성 게이트

지표가 아니라 **통과 조건**이다. 산출기 첫 줄에서 검사하고, 불일치면 지표를

**틀린 숫자가 발표 자료에 들어갔을 것이고, 지표라는 이름이 붙어 있어 아무도

### 8-1. processed 계층 포맷 전환 📄

**클라우드 적재 전에 해야 한다.** 지금은 텍스트·SQLite 라 저장 비용과 스캔이

|---|---|---|
| `*.geojson` | 텍스트. 좌표를 문자열로 저장 | **GeoParquet** |

| 대용량 CSV | 텍스트 | **Parquet** |
| `dem_scope.tif` | 일반 GeoTIFF | **COG** (범위 요청 가능) |

⚠ **`web/data` 는 GeoJSON 을 유지한다.** 브라우저가 읽어야 한다.
⚠ 여러 스크립트가 `gpd.read_file(*.gpkg)` 로 읽고 있다. 한 번에 바꿔야 하고
회귀 위험이 있다. **파이프라인이 안정된 뒤에 한다.**

### 8-2. 클라우드 적재 📄

### 9-3. 주간 멘토링 — 축을 바꿔가며 물어라

매번 "진행 상황"만 보고하면 낭비다.

```

2주  DL 투입 지점 타당성(§5-6)
3주  실험 설계·베이스라인

```

답을 반드시 받아야 하는 셋이다. **셋 다 기술이 아니라 판단이다.**

| # | 질문 | 왜 우리가 못 정하나 |
|---|---|---|
| 1 | 표본 3~5곳으로 1,101구간을 일반화하는 것이 심사에서 방어되나 | 통계 설계 판단 |
| 2 | 영상판정 불가 354 를 통행 가능으로 볼 것인가 | §3-3 오류 비대칭. 안전 정책 판단 |
| 3 | 외부 검증 수단 0개로 중간평가를 받는 것이 맞나 | 심사 감각 |

## 10. 우선순위

### 10-1. 지금 막혀 있는 것

```
🔴 오류 비대칭 결정(§3-3)      ← 결손 처리와 불확실 취급이 여기 걸려 있다
🟡 평가지표 산출(§7-2)         ← 설계 완료. E-1 · E-2 미착수
🟡 CCTV_RANGE 미확인           ← 354구간(회색 전부)의 판정을 가른다
⏳ 소방차 실제 제원             ← D-30. TRUCK 3.0 의 근거 보강
⏳ 소화전 589개 좌표            ← D-30
🔴 실측 DB · 입력 화면(HTTPS)   ← 다음 실측을 막고 있는 유일한 항목
```

### 10-2. 순서

```
STEP 1  경계 확보 · 폭 산출                       완료
STEP 2  그래프 구축 + 다익스트라 / A*              다익스트라 완료 · A* 미착수
        → 일방통행·회전제한 투입 · 시나리오 자동 탐색
STEP 3  관측점 선정 → 기준점 실측 → 3회 촬영
        → 선정 기준은 §6-2 에 데이터로 정의됨
STEP 4  mock 서버 / 프라이버시 파이프라인 / 야간 강건성
STEP 5  평가지표 산출 → 발표 스토리라인
```

**의존 관계** — `경계 → 노딩 → 폭 → 그래프 → 시나리오 → 관측점 → 촬영`.

**시나리오 자동 탐색이 답사보다 먼저다.** 순서가 꼬이면 엉뚱한 골목을 찍고
답사가 통째로 날아간다.

### 10-3. 병렬로 돌릴 수 있는 것

- 평가지표 산출 E-1 · E-2 (§7-2) ← 정의는 끝났다
- 소방서 인터뷰 전화(§9-1)
- 그래프 방향성 결정(§4-5) ← 안 정하면 코드를 두 번 갈아엎는다
- mock 서버 프레임 시퀀스 구조 설계
- 계약 테스트 확충 — 폭 상한 · 도로명 규칙 위반 상한 · 조용한 결측
