# 지시문 원본 — `docs/batches/`

DECISIONS 는 「지시문」을 92번 가리키는데(감사 2026-10-24) **저장소에 지시문 원본이 한 건도 없었다.**
그래서 「지시문의 열셋」 · 「지시문 0.62배」 같은 문장은 읽는 사람이 **무엇을 근거로 한 말인지 확인할 수 없다.**
이 디렉터리가 그 원본을 둘 자리다.

## 규약

1. **파일 이름은 `Zm<번호 두 자리>.md` 다.** 배치 하나에 파일 하나 — `Zm03.md` ~ `Zm20.md`.
2. **원본은 사용자가 복원해서 넣는다.** 에이전트는 이 디렉터리에 원본을 쓰지 않는다 — 기억으로 되살린 지시문은
   원본이 아니다. 디렉터리와 이 표와 인용 규약만 에이전트가 세운다.
3. **DECISIONS 가 「지시문」을 인용하면 그 파일을 가리킨다.** 꼴은 `(지시문 docs/batches/Zm19.md)` 다.
   원본이 아직 없는 판이면 `(지시문 원본 없음 · Zm19)` 라고 **없다고 적는다.** 가리키지도 않고 없다고도
   안 적은 인용은 `tests/test_batches_index.py` 의 래칫이 센다 — 새로 늘면 운다.
4. **표(아래)가 정본이다.** 파일을 넣으면 그 줄의 상태를 `있음` 으로 바꾼다. 표와 실물이 다르면 시험이 운다
   (파일이 있는데 `원본 없음` 이거나, 없는데 `있음`).
5. 파일 맨 위에는 **받은 날짜와 복원 경위**를 한 줄로 적는다(사용자가 대화 기록에서 복원했는지, 보관본인지).
   원문은 고치지 않는다 — 오타도 그대로 둔다. 문체 요지화(`tools/tonecheck.py`)는 **DECISIONS 쪽** 인용에 적용되고
   이 원본 파일은 사람 말 그대로 보관하는 자리다. 그래서 `tonecheck` 의 범위 밖이다(`docs/batches/` 는 `DOCS` 에 없다).
