이거 빠지면 커밋 시점 검사가 안 돌고 CI 에서 뒤늦게 잡힌다. 그때는 이미 히스토리에 박혀 있다.

매체 저장 — 버킷 둘

버킷내용보관
1차얼굴·번호판 마스킹만. 기하 보정 전지우지 않는다
2차왜곡 보정 · 호모그래피 적용 완료화면 표시는 presigned URL
★ 1차를 남기는 이유는 둘이다 — 판정이 틀렸을 때 되짚을 대상이 그것뿐이고, 호모그래피·캘리브레이션 값이 바뀌면 1차에서 다시 계산해야 한다. 2차만 남기면 파라미터를 고칠 때마다 재촬영이다.
키는 seg_uid 로 시작한다. src/contracts/vision.py 의 SEG_UID_RE 가 이미 그 형식을 강제하므로 계약이 저장소 배치까지 덮는다.
⚠ 어느 버킷에도 미마스킹 프레임을 두지 않는다. 마스킹은 업로드 전에 끝난다. 1차 버킷이 "원본 보관소" 가 되는 순간 이 설계의 전제가 무너진다.

⚠ 사진은 저장소에 넣지 않는다. web/data 40MB 상한과 같은 이유다 — 한 번 커밋되면 히스토리에서 뺄 수 없다.

7 · 한시 완화 대장

⚠ 지금 두 건이 낮아져 있다. §4 룰셋 표는 목표값이고 아래가 현재값이다. PLAN #51 이 열려 있다.

⚠ Code Owners 가 꺼져 있으면 CODEOWNERS 는 효력 없는 텍스트 파일이다. 파일이 저장소에 있다는 것과 리뷰가 강제된다는 것은 다르다. 이 줄이 남아 있는 동안 코어 파일은 아무나 고쳐서 머지할 수 있다.

⚠ 한시는 적어두지 않으면 영구가 된다. 이 저장소는 같은 형태로 한 번 당했다 — contract-strict 가 --ignore 110개로 넓혀진 채 Required 로 초록불을 뜨는 물건이 됐다(DECISIONS §76).
★ 승인을 낮춰도 검사는 낮추지 않는다. 승인은 사람이고 검사는 기계다. contract-shared 가 죽으면 이 저장소를 지키는 것이 아무것도 안 남는다.

★ 원복은 main → dev 순서다. part/** 에는 끝까지 승인을 걸지 않는다 — 5인이서 3단 승인은 돌아가지 않는다.
⚠ 강제자가 없다. 룰셋은 저장소 밖이라 코드가 못 본다. 지금 이 표는 사람이 손으로 적는다. gh api repos/:owner/:repo/rulesets 를 읽어 §4 표와 대조하는 잡을 contract.yml 에 붙이면 누가 승인 수를 내리는 순간 CI 가 운다 — PLAN #51.
★ 완화할 때 지킬 것 셋.
① 이 표에 먼저 적는다. 내리고 나서 적으면 안 적는다.
② 내린 날을 쓴다. "작업 끝나면" 은 날짜가 아니다.
③ 원복하면 지우지 말고 현재 칸만 되돌린다. 이력이 다음 판단의 근거다.
