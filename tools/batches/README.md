# tools/batches — 한 번 돌고 끝난 배치

여기 있는 것은 **일회성**이다. 이미 돌았고 다시 안 돈다.

## 지우지 않는 이유

무엇을 왜 바꿨는지가 git 로그보다 여기 잘 적혀 있다. 각 스크립트의
머리말이 그 배치의 판단 근거를 담고 있고, 다음에 비슷한 상황이 오면
그것부터 읽는다.

전부 멱등이라 다시 돌려도 안전하지만 돌 이유가 없다 — 이미 적용된
상태를 감지하고 "변경 없음" 을 낸다.

## 여기 있으면 안 되는 것

**유지 검사는 여기 두지 않는다.** 배치가 세운 상태가 유지되는지는
`tools/` 의 재현적 도구가 본다.

| 배치가 세운 것 | 유지를 보는 도구 |
|---|---|
| 제공기관 state · norm 명명 규칙 | `lakecheck` L1 · L6 |
| 격리 잔재 · landing 우회 · norm 계보 | `lakecheck` L2 · L3 · L5 |
| 대장 ↔ 취득 규칙 매칭 | `intake --plan` |
| 폐기 대장 관문 | `intake` 자체 |
| 다운로드·레이크 정리 | `sweep` |
| 임계값 정본 (B3) | `widen W2` ★ 아직 verify.sh 에 배선 안 함 |
| 규칙 조립 정본 (B3) | `test_place_idempotent` · `test_normalize_rules` |

검사를 두 벌 만들지 않는다. 그것이 이 저장소가 232번 당한 형태다.

## 판별식

    "내년에도 이걸 돌릴 일이 있나"
      있다  →  tools/           이름에 배치 번호를 안 단다
      없다  →  tools/batches/   b2_ 처럼 배치 번호를 단다


## B3 — 사본 제거 (2026-09-11)

`b3.sh` 가 아래 셋을 순서대로 돌린다. **스냅샷 기반**이라 적용 전 원본을
`$TMPDIR/fire-lane-b3/rollback` 에 통째로 보관하고 `--rollback` 으로 되돌린다.

    bash tools/batches/b3.sh              무엇이 바뀌는지만
    bash tools/batches/b3.sh --apply      적용 + 검증
    bash tools/batches/b3.sh --rollback   되돌리기

| 배치 | 닫은 것 | 지문 |
|---|---|---|
| `b3_params` | 임계값 3벌 — `COV_MIN` · `NODE_TOL` · `TRUCK` | 불변 (값 대조 통과) |
| `b3_const` | 인코딩 후보 4벌 · `TEXT_EXT` 3벌 | 불변 (**합치지 않고 모으기만**) |
| `b3_rules` | 규칙 조립 **4벌** — `passthrough_rules()` | 불변 (main() 조립 동일) |

### B3 인데 B3 가 아니었던 것 — B4 로 옮긴다

감사가 81건을 전부 **"지문 불변"** 으로 분류했는데, 열어보니 아니었다.
아래 셋은 합치는 순간 판정이 바뀐다. 재잠금 절차를 타야 하므로 **B4** 다.

| 항목 | 왜 불변이 아닌가 |
|---|---|
| 인코딩 후보 4벌 **통합** | 순서가 다르다. `cp949` 를 먼저 보면 UTF-8 도 "읽히고" 모지바케가 된다. `encoding.py` 머리말이 이미 적어놨다 — *"판별 순서가 곧 신뢰도 순서다"* |
| `TEXT_EXT` 3벌 **통합** | 셋이 다른 질문에 답한다. 자료 형식 판별 · 전처리 대상 · **저장소 소스** 검사. 같은 이름을 쓴 것이 잘못이지 값이 다른 것이 잘못이 아니다 |
| union-find 5벌 · 등거리 근사 3벌 | 구현 동치성이 확인되지 않았다. 노드 묶음이 달라지면 `seg_uid` 가 움직이고 그건 산출물 변경이다 |

`b3_const` 가 앞의 둘에 대해 한 일은 **모으기**다. 값과 순서를 한 글자도
안 바꾸고 `encoding.py` 한 곳에 이름을 달리해 올렸다. 그래서
⒜ 정본 파일이 하나가 되고 ⒝ **차이가 한 화면에 보인다.**
합칠지는 B4 에서 사람이 근거를 놓고 정한다.

### 남은 B3 — 색 사본 5벌

`web/js` 의 다크 색값이 레이어 생성부(`mask.js` · `minimap.js`)와
테마 전환부(`theme.js`)에 두 벌씩 있다. 같은 값이라 지문은 불변이지만
새 모듈(`palette.js`)을 하나 만들어야 하고, 그러면
`js_graph_check` · `web_manifest` · `test_web_ownership` 이 운다.
**배선까지가 배치다**(원칙 ③). 따로 연다.

### 이 배치가 값을 치른 것

    ① 사본을 지우기 전에 값을 대조한다
       세 임계값이 정본과 같은지 AST 로 다시 봤다. 하나라도 달랐으면
       사본 제거가 아니라 판정 변경이고 B4 다. 스크립트가 멈추게 해놨다.

    ② 멱등 판정을 "새 문자열이 이미 있나" 로 하면 안 된다
       삭제 편집의 새 문자열은 원문의 부분집합이라 처음부터 참이 된다.
       `TRUCK = 3.0` 이 안 지워진 채 "이미 적용됨" 이 떴다. done 마커를 쓴다.

    ③ import 를 "머리 블록 끝" 에 붙이면 두 가지로 틀린다
       `inventory.py` 는 196줄에 `# noqa: E402` 늦은 import 가 있어서
       사용처보다 아래에 꽂혔다(NameError). 끝에 붙이면 isort 가 깨져
       `ruff I001` 이 운다 — verify.sh 통과가 21 → 20 으로 떨어졌다.
       **두 번 다 검사가 잡았다.** first-party 그룹의 알파벳 자리에 끼운다.

    ④ 스냅샷을 `.work/` 에 두면 안 된다
       `tools/tidy.py` 가 `.work` 를 파이프라인 임시로 알고 지운다.
       verify.sh 를 돌리고 나면 보관본이 없어 `--rollback` 이 죽는다.
       저장소 밖(`$TMPDIR`)에 둔다.

    ⑤ 감사가 셋이라고 센 것이 넷이었다
       `tests/test_normalize_rules.py` 는 `EXT` 리터럴을 43줄(전역)과
       265줄(테스트 지역)에 두 번 갖고 있었다. 감사 건수는 하한이다.
